📐 Padrões de Projeto Utilizados

Esta aplicação implementa 4 padrões de projeto de forma integrada em um sistema de pedidos de lanchonete.

1. Singleton — singleton.py

Categoria: Criacional

Problema: Precisamos de um único ponto de configurações globais da lanchonete (nome, taxa de entrega, tempo médio de preparo). Se cada parte do código criar sua própria instância, pode haver inconsistência.

Solução: A classe ConfiguracaoLanchonete garante que só existe uma instância em toda a aplicação. Qualquer chamada retorna sempre o mesmo objeto.

Onde ver: views.py, funções home() e sobre_padroes().

2. Factory Method — factory.py

Categoria: Criacional

Problema: Existem três tipos de pedido (Balcão, Entrega, Mesa), cada um com comportamentos diferentes (ex: taxa extra na entrega). Usar if/elif espalhado pelo código tornaria a manutenção difícil.

Solução: A classe FabricaPedido centraliza a criação. O código cliente apenas chama FabricaPedido.criar(tipo=...) e recebe o objeto certo.

Onde ver: views.py, função novo_pedido().

3. Observer — observer.py

Categoria: Comportamental

Problema: Quando o status de um pedido muda, múltiplas partes do sistema precisam ser notificadas (cozinha, cliente, etc.). Acoplar isso diretamente nas views tornaria o código rígido.

Solução: O GerenciadorStatus mantém uma lista de observadores. Quando notificar_todos() é chamado, todos os observadores registrados reagem automaticamente, sem que a view precise saber quem são.

Onde ver: views.py, funções novo_pedido() e atualizar_status().

4. Strategy — strategy.py

Categoria: Comportamental

Problema: O sistema aceita múltiplas formas de pagamento (Dinheiro, Cartão, Pix), cada uma com sua lógica de processamento. Usar condicionais (if pagamento == "pix": ...) viola o princípio aberto/fechado.

Solução: Cada forma de pagamento é uma classe separada que implementa a interface FormaPagamento. A função obter_forma_pagamento() seleciona a estratégia certa em tempo de execução.

Onde ver: views.py, função novo_pedido().

💡 Como os padrões se integram

  1. O Singleton fornece as configurações que influenciam o comportamento de todo o sistema.
  2. A Factory cria o pedido do tipo correto, já com a lógica de cálculo de total embutida.
  3. O Strategy processa o pagamento de acordo com a forma escolhida pelo cliente.
  4. O Observer dispara notificações automáticas para todos os interessados quando o pedido muda de estado.
